# Decision Table Toolkit

条件と動作・結果を型付きの決定表に整理する、ローカルのブラウザアプリです。単一HTMLをChromeで開いて利用できます。サーバー・AI API・ネットワーク接続は実行時に必要ありません。

## 起動

[ビルド済みHTML](releases/decision-table-toolkit-v0.1.0.html)をダウンロードし、Chromeで開いてください。自分でビルドした場合は `dist/decision-table-toolkit.html` を使用します。画面の「サンプルを開く」から編集・検証・統合・JSON保存を試せます。現在は初期開発版で、対応対象はPCのChromeのみです。

1. 「＋ 条件」でBoolean / Enum / Number / String / Dateと有限の候補・区間を定義します。
2. 「＋ 動作・結果」で動作の実行有無または型付き結果を定義します。
3. 「組み合わせを生成」し、各規則の結果を入力します。
4. 「検証」で未設定・重複・網羅性を確認します。
5. 「まとめる」で等価性を確認できた候補を表示し、承認したものだけ反映します。
6. JSONで保存・再読込できます。外部AIが編集したJSONも同じ形式検証を通ります。

規則は上から順に全件適用する仕様として扱います。実業務処理や条件判定コードは実行しません。JIS X 0125を参照していますが、完全準拠を保証する製品ではありません。

## JSONと統合

[交換形式のSchema](schemas/decision-table.schema.json)の版は `1.0` です。未知フィールド・未知版・型不正・参照不正は拒否します。作成途中の結果は明示的な `unset` として保存できます。数値は精度を保つ10進文字列、日付は `YYYY-MM-DD` です。

元の組み合わせ数、現在の規則数、結果パターン数は別です。10×10は100件を生成します。同じ結果の条件はORで正確にまとめ、元にない組み合わせを追加しません。多重適合の順序・回数が変わる場合は統合しません。20〜30という想定は統合後の結果パターン数で、生成上限ではありません。

初期の展開・等価性確認は10,000組み合わせまでです。診断・証明にも計算予算があり、超過した候補を等価と表示しません。多くの規則がある場合、表は40規則ずつ表示します。

## ファイルとの継続的な確認

Chromeのファイル選択で連携したJSONは、前景で約1秒ごとに再確認します。外部変更は通知し、取込承認前は編集内容を置き換えません。双方変更は競合として扱います。バックグラウンド中は検知が遅れるため、復帰時に再確認します。

同じファイルを外部ツールと同時に保存しないでください。ブラウザだけでは任意の外部アプリを含む排他・CASを保証できません。保存前に外部ツールを停止するか、別名へ退避してください。保存直前と開始時に外部変更を確認し、close後の再読込で保存内容の一致を確かめます。失敗時に編集中データを破棄しません。

APIや権限が使えない環境では明示読込・ダウンロード方式となり、継続確認はできません。ダウンロードの開始は実ファイルの保存完了とは区別します。編集中データはメモリ上にあるため、ページを閉じる前に保存してください。

## 開発・検証

動作確認環境: Node.js 26.5.0 / npm 11.17.0 / TypeScript 5.9.3、macOS上のChrome。テストはNodeのTypeScript直接実行機能を使用します。

```sh
npm install
npm run typecheck
npm test
npm run build
```

通常ビルドはesbuildでIIFEを作成し、JS/CSSを1つのHTMLへ同梱します。実行時に外部資産を読み込みません。型検査はesbuildによる変換とは別に行います。

### 制限環境での検証用ビルド

今回の実行環境ではnpmレジストリの名前解決が失敗し、esbuildの取得・通常ビルドは未検証です。利用可能なTypeScriptコンパイラで、固定した内部モジュールを同梱する明示的な検証経路を用意しました。

```sh
npm run build:offline
```

これはTypeScriptパッケージ自体が利用可能な環境で動く検証用ビルドです。依存取得を不要にするコマンドではありません。生成されたHTMLの起動、サンプル統合、JSON保存・再読込、外部変更と競合通知をChromeの `file://` で確認しました。esbuild版と同じビルドを検証済みとは報告しません。

型検査と37テストは成功しています。対象を絞る場合は `node --test tests/core.test.ts`、`node --test tests/files.test.ts`、`node --test tests/app.test.ts` を利用します。`npm test` には単一HTMLの構文・資産同梱検査も含まれます。

公開版にはアプリ・テスト・サンプル・交換形式・ビルド済みHTMLを含みます。開発用の内部資料は含みません。初版のHTMLは上記の検証用ビルドで生成しています。
