# Decision Table Toolkit

条件と動作・結果を型付きの決定表に整理する、ローカルのブラウザアプリです。単一HTMLをChromeで開いて利用できます。サーバー・AI API・ネットワーク接続は実行時に必要ありません。

## 起動

[ビルド済みHTML](releases/decision-table-toolkit-v0.1.0.html)をダウンロードし、Chromeで開いてください。自分でビルドした場合は `dist/decision-table-toolkit.html` を使用します。画面の「サンプルを開く」から編集・検証・統合・JSON保存を試せます。現在は初期開発版で、対応対象はPCのChromeのみです。

ビルド済みHTML（v0.1.0）には、下記の「＋ 規則」による規則の記述、条件の「すべて」、「結果を確認」、10,000組み合わせを超える表の検証は含まれていません。これらはソースからビルドすると利用できます。

1. 「＋ 条件」でBoolean / Enum / Number / String / Dateと有限の候補・区間を定義します。
2. 「＋ 動作・結果」で動作の実行有無または型付き結果を定義します。
3. 「＋ 規則」で規則を1行ずつ追加し、条件のセルで対象の区分を選びます。「すべて」のままにした条件は、どの区分にも一致します。組み合わせが少ない表は「組み合わせを生成」で全件の規則を作ることもできます（10,000組み合わせまで）。各規則の結果を入力します。
4. 「検証」で未設定・重複・未網羅・矛盾を確認します。同じ入力に違う結果の規則が適合する場合は、矛盾として規則番号と条件の範囲を示します。規則のない入力は「条件1=A / 条件2=B・C / 他の条件はすべて」のような条件のかたまりと件数で示します。
5. 表の下の「結果を確認」で条件の区分を選ぶと、その条件に適用される結果だけを表示します。選ばない条件は指定なしとして扱い、フィルタのように絞り込めます。表は変更しません。
6. 「まとめる」で、どの入力についても結果が変わらないと確認できた候補を表示し、承認したものだけ反映します。同じ結果の規則は、重なっていても1つにまとめ、条件を整理します。全区分がそろった条件は「すべて」になります。「すべて繰り返し適用」で、候補がなくなるまで繰り返した結果を一度に承認できます。
7. JSONで保存・再読込できます。外部AIが編集したJSONも同じ形式検証を通ります。

この表は「1つの入力に対して結果は1つ」として扱います。同じ入力に複数の規則が適合してもよいのは、その結果がすべて同じ場合だけです。結果が違う規則が同じ入力に適合する場合は矛盾で、「検証」が指摘します。規則の並び順は結果に影響しません。実業務処理や条件判定コードは実行しません。JIS X 0125を参照していますが、完全準拠を保証する製品ではありません。

## JSONと統合

[交換形式のSchema](schemas/decision-table.schema.json)の版は `1.0` と `1.1` です。`1.1` では規則の `selections` から条件を省略でき、省略した条件はその条件の全区分に一致します（あとから区分を追加しても含みます）。区分を列挙した条件は、列挙した区分だけが対象です。`1.0` では各規則で全条件の指定が必要で、省略は拒否します。新しく作る表は `1.1` で保存し、`1.0` のファイルも読み込めます。未知フィールド・未知版・型不正・参照不正は拒否します。作成途中の結果は明示的な `unset` として保存できます。数値は精度を保つ10進文字列、日付は `YYYY-MM-DD` です。

元の組み合わせ数、現在の規則数、結果パターン数は別です。10×10は100件を生成します。同じ結果の条件はORで正確にまとめ、元にない組み合わせを追加しません。統合の前後で、どの入力についても結果が変わらないことを確認します。20〜30という想定は統合後の結果パターン数で、生成上限ではありません。

全組み合わせの生成と、全件を列挙する確認（結果パターン数など）は10,000組み合わせまでです。これを超える表でも、未網羅と矛盾の検証、統合候補、条件を指定した展開表示は利用できます。未網羅は全件を列挙せずに求めます。10,000組み合わせを超える表の統合候補は、まとめた後の条件が元の規則と同じ入力に一致することを証明できたものだけを表示します。計算予算を超えた場合は判定できていないと表示し、問題なし・等価とは表示しません。多くの規則がある場合、表は40規則ずつ表示します。

## ファイルとの継続的な確認

Chromeのファイル選択で連携したJSONは、前景で約1秒ごとに再確認します。外部変更は通知し、取込承認前は編集内容を置き換えません。双方変更は競合として扱います。バックグラウンド中は検知が遅れるため、復帰時に再確認します。

同じファイルを外部ツールと同時に保存しないでください。ブラウザだけでは任意の外部アプリを含む排他・CASを保証できません。保存前に外部ツールを停止するか、別名へ退避してください。保存直前と開始時に外部変更を確認し、close後の再読込で保存内容の一致を確かめます。失敗時に編集中データを破棄しません。

APIや権限が使えない環境では明示読込・ダウンロード方式となり、継続確認はできません。ダウンロードの開始は実ファイルの保存完了とは区別します。編集中データはメモリ上にあるため、ページを閉じる前に保存してください。

## 開発・検証

動作確認環境: Node.js 26.5.0 / npm 11.17.0 / TypeScript 5.9.3、macOS上のChrome。テストはNodeのTypeScript直接実行機能を使用します。

```sh
npm install
npm run typecheck
npm test
npm run build
```

通常ビルドはesbuildでIIFEを作成し、JS/CSSを1つのHTMLへ同梱します。実行時に外部資産を読み込みません。型検査はesbuildによる変換とは別に行います。

### 制限環境での検証用ビルド

npmレジストリに接続できない環境ではesbuildを取得できません。そのため、利用可能なTypeScriptコンパイラで固定した内部モジュールを同梱する明示的な検証経路を用意しています。通常ビルドはesbuild 0.25.12で成功し、生成したHTMLの起動とサンプルの統合操作を確認済みです。

```sh
npm run build:offline
```

これはTypeScriptパッケージ自体が利用可能な環境で動く検証用ビルドです。依存取得を不要にするコマンドではありません。生成されたHTMLの起動、サンプル統合、JSON保存・再読込、外部変更と競合通知をChromeの `file://` で確認しました。これらのファイル操作は検証用ビルドでの確認であり、esbuild版では未確認です。

型検査と68テストは成功しています。対象を絞る場合は `node --test tests/core.test.ts`、`node --test tests/files.test.ts`、`node --test tests/app.test.ts`、`node --test tests/rules.test.ts` を利用します。`npm test` には単一HTMLの構文・資産同梱検査も含まれます。

公開版にはアプリ・テスト・サンプル・交換形式・ビルド済みHTMLを含みます。開発用の内部資料は含みません。初版のHTMLは上記の検証用ビルドで生成しています。
