# Decision Table Toolkit

条件と動作を決定表に整理する、ローカルのブラウザアプリです。単一HTMLをChromeで開いて利用できます。サーバー・AI API・ネットワーク接続は実行時に必要ありません。

用語は JIS X 0125（決定表）に合わせています。ただし規格への完全準拠を保証する製品ではありません（「JISとの関係」を参照）。

## 起動

使い方は2通りあり、どちらも同じHTMLです。

- **Web版**: https://kazuno47.github.io/decision-table-toolkit/ をChromeで開きます。常に最新の版です。以前の版は `https://kazuno47.github.io/decision-table-toolkit/releases/decision-table-toolkit-v0.2.3.html` のように版を指定して開けます。
- **ダウンロード版**: 下のHTMLをダウンロードして、手元のファイルをChromeで開きます。ネットワークにつながっていなくても使え、ファイルを入れ替えない限り中身は変わりません。

どちらの場合も、作成した表や読み込んだJSONはブラウザの中だけで扱い、どこにも送信しません。HTMLは外部への通信を禁止する設定（Content-Security-Policy の `connect-src 'none'`）を含み、外部のスクリプトや画像も読み込みません。Web版は、このリポジトリの `releases/` にあるHTMLをそのまま配信しています（配信のためのビルドは行いません）。

[ビルド済みHTML（v0.3.1）](releases/decision-table-toolkit-v0.3.1.html)をダウンロードし、Chromeで開いてください。自分でビルドした場合は `dist/decision-table-toolkit.html` を使用します。画面の「サンプルを開く」から編集・検証・簡単化・JSON保存を試せます。現在は初期開発版で、対応対象はPCのChromeのみです。

以前の[v0.3.0](releases/decision-table-toolkit-v0.3.0.html)、[v0.2.4](releases/decision-table-toolkit-v0.2.4.html)、[v0.2.3](releases/decision-table-toolkit-v0.2.3.html)、[v0.2.2](releases/decision-table-toolkit-v0.2.2.html)、[v0.2.1](releases/decision-table-toolkit-v0.2.1.html)、[v0.2.0](releases/decision-table-toolkit-v0.2.0.html)と初版の[v0.1.0](releases/decision-table-toolkit-v0.1.0.html)も残しています。版によって表の解釈が異なります（「版による違い」を参照）。v0.1.0はスキーマ1.1のJSONを読み込めません。

1. 「＋ 条件」で条件と、条件のとり得る値を定義します（Boolean / Enum / Number / String / Date。数値と日付は範囲で定義します）。
2. 「＋ 動作」で動作を定義します。動作指定の形式は、X／−で指定する制限指定か、語句・値で指定する拡張指定です。
3. 「＋ 規則」で規則を1つずつ追加します。規則には、関係する条件と、実行する動作だけを書きます。書いた規則は「金額＝3億以上 かつ 種別＝B → 承認者＝監査」「個人情報＝あり → セキュリティチェック＝X」のように1行ずつ並びます。書かなかった条件は無関係、書かなかった動作は指定なしで、どちらもリストには表示しません（決定表では「−」になります）。規則を押すと、条件指定と動作指定をまとめて編集できます。条件の値が少ない表は「全組合せの規則を作成」で、条件指定の全組合せの規則を作ることもできます（10,000組合せまで）。
4. 「検証」で完備性と動作指定を確認します。満足される規則がない条件の組合せは「条件1=A / 条件2=B・C / 他の条件は−」のような範囲と件数で示します。同じ動作に異なる値を指定する規則が同時に満足される場合は、動作指定の不一致として規則番号・条件の範囲・動作名を示します。
5. 規則のリストの下に「決定表（単適合）」を表示します。規則の記述から求めた単適合決定表で、条件と動作を行、規則を列に書いた規格の一般形式の1つの表です。条件の組合せのどの1つも、ただ1つの規則（列）でだけ満足されます。上の例に課長・部長・役員・監査の規則があれば、承認者4通り×セキュリティチェックのX／−で8個の規則になります。各規則の組合せ数と、その合計が条件指定の全組合せに一致するか（規則数の検査）も表示します。条件指定の全組合せが多く1つの表に書き切れない場合は、互いに関係しない動作ごとに複数の決定表に分離して表示します（規格の附属書1「表の分離」にあたります）。各表には、その動作に関係する条件だけが並び、どの表も単適合です。同じ規則が指定する動作は同じ表にまとめ、それでも大きい場合は動作ごとに分けます。計算に時間がかかる場合は、自動更新をやめて「決定表を更新」ボタンで更新します。
6. いちばん下の「決定表の解釈」で条件の値を選ぶと、満足される規則と実行される動作を表示します。決定表の規則番号を押すと、その規則の条件指定がここに入ります。動作が決まらないうちは、どの条件を選べば決まるかを案内します。無関係な条件は選ばなくても決まります。
7. 「簡単化」で、動作指定がすべて同じ規則を結合し、すべての値がそろった条件を条件指定から外します。条件のどの組合せについても動作が変わらないと確認できた候補だけを表示し、承認したものだけ反映します。「繰り返し結合」で、候補がなくなるまで繰り返した結果を一度に承認できます。1回の計算は500回の結合までで、それを超える場合は打ち切ったことを表示します（反映すると続きの候補を表示します）。
8. JSONで保存・再読込できます。外部AIが編集したJSONも同じ形式検証を通ります。

業務処理は実行しません。決定表の内容を他のソフトウェアから使う方法は「他のソフトウェアから使う」を参照してください。

## JISとの関係

JIS X 0125 は単適合決定表（条件の組合せのどの一つも、ただ一つの規則でだけ満たされる表）を対象とし、多重適合決定表は対象にしていません。このツールは次の点で規格の形と異なります。

- **多重適合で記述できます。** 複数の規則が同じ条件の組合せで満足されてもよく、満足された規則の動作指定を動作ごとに合わせて解釈します。制限指定の動作は、満足された規則のどれかが「X」なら実行します。拡張指定の動作は、満足された規則が指定した値を使い、異なる値が指定されていれば不一致として指摘します。画面上部は規則を記述するためのリストで、規格の形の決定表は、その下の「決定表（単適合）」に1つの表として表示します。
- **規則の記述は決定表の形ではありません。** 規則を1行ずつ、「金額＝3億以上 かつ 種別＝B → 承認者＝監査」のように、関係する条件と実行する動作だけを並べたリストです。規格と同じ形（条件・動作を行、規則を列）で表示するのは「決定表（単適合）」の表です。
- **条件指定に複数の値とORを書けます。** 1つの条件指定に複数の値を選べ、1つの規則に複数の条件指定の組（ORブロック）を持てます。
- **補完規則（ELSE）、初期化部、決定表間の関係（順番・選択・反復・入れ子）は扱いません。** 大きな表を動作ごとに分離して表示しますが、分離した表同士の順番・選択の関係は記述しません（互いに独立に解釈できる表です）。
- **動作の実行順序は扱いません。** 規則の順番は、規格と同じく意味をもちません。

## 版による違い

| 版 | 同じ条件の組合せで複数の規則が満足されたとき |
|----|----------------------------------------------|
| v0.1.0 | 満足された規則を全件、上から順に適用する |
| v0.2.0 | 規則の動作指定全体が同じでなければ不一致とする |
| v0.2.1 | 動作ごとに合わせる。制限指定はどれかが「X」なら実行、拡張指定は値が異なれば不一致 |

v0.2.2では、規則の記述を「関係する条件だけを書く」表示に改め、決定表（単適合）を独立した1つの表にして、規則番号から「決定表の解釈」へ値を反映できるようにしました。v0.2.3では、規則の記述を表ではなくリストにしました。規則は「条件 → 動作」の形で1行ずつ並び、指定した条件と動作だけを表示します。v0.2.4では、1つの表に書き切れない大きな決定表を、動作ごとの複数の決定表に分離して表示するようにしました。表の解釈はv0.2.1と同じです。 v0.3.0では、表の解釈は変えずに、他のソフトウェアから使う判定エンジンを追加しました。v0.3.1では、条件や動作の定義を編集したときに、変更していない値・規則・動作指定が失われる不具合を修正しました（複数の候補を1つの値にまとめた条件、Enumの候補を追加・並べ替えした動作）。あわせて、分離した決定表で、条件によらず指定された動作の値と不一致を表示するようにし、繰り返し結合が上限で止まった場合にその旨を表示するようにしました。

v0.2.1では画面の用語を規格に合わせました。以前の版との対応は次のとおりです。

| 以前の表示 | v0.2.1 |
|------------|--------|
| 動作・結果、出力 | 動作（制限指定・拡張指定） |
| 区分 | 条件の値 |
| すべて | −（無関係） |
| 実行する／実行しない／未設定・決めない | X／−（制限指定の「実行しない」と未設定は同じ「−」） |
| 元の組み合わせ | 条件指定の全組合せ |
| 未網羅 | 完備していない（完備性） |
| 矛盾 | 動作指定の不一致 |
| まとめる | 簡単化（規則の結合） |
| 結果を確認 | 決定表の解釈 |
| 結果パターン | 決定表（単適合）の規則。画面上部の件数は「動作指定の組合せ」 |
| 適合する | 満足される |

## JSONと簡単化

[交換形式のSchema](schemas/decision-table.schema.json)の版は `1.0` と `1.1` です。`1.1` では規則の `selections` から条件を省略でき、省略した条件は条件指定「−」（無関係）で、あとから値を追加しても対象に含みます。値を列挙した条件は、列挙した値のときだけ満足されます。`1.0` では各規則で全条件の指定が必要で、省略は拒否します。新しく作る表は `1.1` で保存し、`1.0` のファイルも読み込めます。未知フィールド・未知版・型不正・参照不正は拒否します。

動作指定「−」は `unset` として保存します。制限指定の動作では `false` も「−」として読みます。数値は精度を保つ10進文字列、日付は `YYYY-MM-DD` です。JSONのキー名（`outputs`、`partitions` など）は以前のままで、画面の用語とは異なります。

条件指定の全組合せの数、記述した規則の数、決定表（単適合）の規則の数は別です。条件の値が10個と10個なら全組合せは100件です。簡単化は、動作指定が同じ規則をORで正確に結合し、元にない組合せを追加しません。簡単化の前後で、条件のどの組合せについても動作が変わらないことを確認します。

全組合せの規則の作成と、全組合せを列挙する確認は10,000組合せまでです。これを超える表でも、完備性と動作指定の検証、簡単化、解釈、決定表（単適合）の表示は利用できます。決定表は、全組合せが数十兆件の表でも、動作ごとに分離することで表示できます。これらは全組合せを列挙せずに求めます。10,000組合せを超える表の結合候補は、結合後の条件指定が元の規則と同じ範囲に一致することを証明できたものだけを表示します。計算予算を超えた場合は判定できていないと表示し、完備・等価とは表示しません。多くの規則がある場合、表は40規則ずつ表示します。

## ファイルとの継続的な確認

Chromeのファイル選択で連携したJSONは、前景で約1秒ごとに再確認します。外部変更は通知し、取込承認前は編集内容を置き換えません。双方変更は競合として扱います。バックグラウンド中は検知が遅れるため、復帰時に再確認します。

同じファイルを外部ツールと同時に保存しないでください。ブラウザだけでは任意の外部アプリを含む排他・CASを保証できません。保存前に外部ツールを停止するか、別名へ退避してください。保存直前と開始時に外部変更を確認し、close後の再読込で保存内容の一致を確かめます。失敗時に編集中データを破棄しません。

APIや権限が使えない環境では明示読込・ダウンロード方式となり、継続確認はできません。ダウンロードの開始は実ファイルの保存完了とは区別します。編集中データはメモリ上にあるため、ページを閉じる前に保存してください。

## 他のソフトウェアから使う（判定エンジン）

このツールで作った決定表のJSONを、別のソフトウェアから読み込んで解釈するための部品です。画面の「決定表の解釈」と同じ処理を、依存のない1つのESモジュールにまとめています。ブラウザでもNode.jsでも動きます。外部への通信はせず、動作の実行もしません。返すのは「どの動作が実行されるか」だけです。

- [decision-table-engine-v0.3.1.js](releases/decision-table-engine-v0.3.1.js)（本体）
- [decision-table-engine-v0.3.1.d.ts](releases/decision-table-engine-v0.3.1.d.ts)（TypeScriptの型定義）

2つのファイルを自分のプロジェクトにコピーして使います。版ごとにファイル名が変わるので、取り込んだ版が勝手に変わることはありません。

```js
import { load, conditions, classify, evaluate } from './decision-table-engine-v0.3.1.js';

const table = load(jsonText);            // 読み込みと検証（画面と同じ検証。不正なら例外）
conditions(table);                       // 入力画面を作るための条件と値の一覧

// 条件の値を、定義された値のIDまたはラベルで渡す（条件はIDまたは名前で指定）
let result = evaluate(table, { 金額: '3億以上' });
result.decided;                          // false: まだ決まらない動作がある
result.needed;                           // ['pii'] のように、あと必要な条件のID
result.actions;                          // 動作ごとの状態・実行の有無・値

// 生の値を、定義された値へ当てはめてから解釈する
result = evaluate(table, classify(table, { 金額: 350000000, 個人情報: true }));
result.actions.map(a => [a.name, a.executed, a.value]);
// [['承認者', true, '役員'], ['セキュリティ部門のチェック', true, true]]
```

| 関数 | 内容 |
|------|------|
| `load(source)` | JSON文字列またはオブジェクトを検証して表を返します |
| `conditions(table)` / `actions(table)` | 条件（ID・名前・型・値）と動作（ID・名前・種別）の一覧です |
| `classify(table, values)` | 生の値（真偽・文字列・数値・日付 `YYYY-MM-DD`・値なしの `null`）を、定義された値のIDに当てはめます。どの値にも当てはまらなければ例外です。桁の多い数値は文字列で渡してください |
| `evaluate(table, picks)` | 条件の値から、動作ごとの結果を返します。条件は一部だけでも構いません |

`evaluate` が返す動作ごとの `status` は次の4つです。

| status | 意味 | executed | value |
|--------|------|----------|-------|
| `determined` | 実行する。残りの条件が何であっても同じ | `true` | 制限指定は `true`、拡張指定はその値 |
| `none` | 実行しない（決定表の「−」）。この範囲に、この動作を指定する規則がない | `false` | `null` |
| `open` | まだ決まらない。`needed` の条件を与えると決まる | `null` | `null` |
| `conflict` | 動作指定の不一致。同じ動作に異なる値を指定する規則が同時に満足される | `null` | `null` |

表にない名前のキーは無視し、`ignored` で返します。存在しない値や、同じ名前の条件が複数ある場合の名前指定は例外にします。条件の組合せの数が非常に多い表で条件を一部しか与えない場合、計算の打ち切りにより、決まっている動作が `open` と返ることがあります（誤って `determined` を返すことはありません）。

複数の決定表の関係（順番や選択）や、入力の保存・引き継ぎは扱いません。それらは利用する側で持ってください。公開する関数の形は版によって変わることがあります。

## 開発・検証

プルリクエストとmainへのpushごとに、GitHub Actionsで型検査・テスト・ビルドを実行し、ビルド結果が `releases/` の最新版のHTML・判定エンジンと1バイトも違わないことを確認します（[CI](.github/workflows/ci.yml)）。mainへのマージ後、`package.json` の版に対応する `releases/` のHTMLをGitHub Pagesへ配信します（[Pages](.github/workflows/pages.yml)）。

動作確認環境: Node.js 26.5.0 / npm 11.17.0 / TypeScript 5.9.3、macOS上のChrome。テストはNodeのTypeScript直接実行機能を使用します。

```sh
npm install
npm run typecheck
npm test
npm run build
```

通常ビルドはesbuildでIIFEを作成し、JS/CSSを1つのHTMLへ同梱します。実行時に外部資産を読み込みません。型検査はesbuildによる変換とは別に行います。

### 制限環境での検証用ビルド

npmレジストリに接続できない環境ではesbuildを取得できません。そのため、利用可能なTypeScriptコンパイラで固定した内部モジュールを同梱する明示的な検証経路を用意しています。通常ビルドはesbuild 0.25.12で成功し、生成したHTMLの起動とサンプルの統合操作を確認済みです。

```sh
npm run build:offline
```

これはTypeScriptパッケージ自体が利用可能な環境で動く検証用ビルドです。依存取得を不要にするコマンドではありません。生成されたHTMLの起動、サンプルの簡単化、JSON保存・再読込、外部変更と競合通知をChromeの `file://` で確認しました。これらのファイル操作は検証用ビルドでの確認であり、esbuild版では未確認です。

型検査と79テストは成功しています。対象を絞る場合は `node --test tests/core.test.ts`、`node --test tests/files.test.ts`、`node --test tests/app.test.ts`、`node --test tests/rules.test.ts` を利用します。`npm test` には単一HTMLの構文・資産同梱検査も含まれます。

公開版にはアプリ・テスト・サンプル・交換形式・ビルド済みHTMLを含みます。開発用の内部資料は含みません。v0.2.0以降のHTMLは通常ビルド（esbuild）で生成しています。v0.1.0は検証用ビルドで生成したものです。v0.2.0以降は起動と画面操作をlocalhost経由で確認しており、`file://` で開いてのファイル保存・再読込・外部変更の確認はまだ行っていません。
